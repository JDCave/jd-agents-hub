# Resume Standards — Writing Rules (zh + en markets)

The rules the lint enforces mechanically, plus the ones only a reviewer can
judge. Both Chinese and English job markets are first-class; where they
diverge, both conventions are given. Source: distilled AI Agent resume
guidance (STAR quantification, six golden rules, verb tiers, ATS delivery).

## 1. STAR + quantification

Every project bullet: Situation → Task → Action → Result, with the result
quantified.

- ❌ zh `负责项目开发工作，参与了相关功能的设计和实现。`
- ✅ zh `主导设计并实现了基于 ReAct 循环的 AI Agent 系统，集成 12 个 MCP 工具，
  支撑日均 5000+ 次对话请求，用户问题解决率从 60% 提升至 85%。`
- ❌ en `Participated in development of the agent product.`
- ✅ en `Led design of a ReAct-based AI agent serving 5,000+ conversations
  per day with 12 integrated MCP servers; resolution rate improved from
  60% to 85%.`

## 2. Six golden rules (both markets)

| Rule | Practice |
|---|---|
| 数字说话 / Numbers speak | Quantify every result (提升 X% / improved by X%) |
| 技术栈明确 / Named stack | List the stack per project |
| 深度优于广度 / Depth beats breadth | 2 deep projects > 5 shallow ones |
| 关键词匹配 / Keyword match | Reorder/emphasize keywords per target JD |
| 结果导向 / Outcome orientation | "解决了什么问题 / what problem solved" > task lists |
| 一页为佳 / One page | zh: one A4 page; en: one page, two acceptable for 10+ years |

## 3. Verb tiers (ownership language)

| Tier | zh | en |
|---|---|---|
| Strong | 主导、设计、架构、研究、优化 | led, designed, architected, researched, optimized |
| Medium | 实现、开发、集成、搭建 | built, implemented, developed, integrated |
| Banned | 参与、协助、帮助、参加 | participated, assisted, helped |

## 4. Proficiency honesty

- zh ladder: 精通 > 熟悉 > 了解
- en ladder: expert > proficient > familiar

精通 / expert is a heavy word — interviewers probe it first. Cap mastery
claims at 3; downgrade any uncertain claim one level (熟悉 / proficient).

## 5. Project block — 7 required elements

1. 项目名称 + 时间段 / Name + dates (`YYYY.MM - YYYY.MM` or `Mon YYYY – Mon YYYY`)
2. 项目角色 / Role (独立研究 / 核心开发 / 技术负责人; independent / core dev / tech lead)
3. 技术栈 / Tech stack (one line)
4. 项目描述 / Summary (2–3 sentences: scene, scale, goal)
5. 核心职责 / Responsibilities 3–5 bullets, verb-first
6. 量化成果 / Results 1–2 bullets, each with a number
7. (Optional) 可验证链接 / verifiable links — repo, docs, blog

## 6. Section conventions per market

| Aspect | zh market | en market |
|---|---|---|
| Headings | 教育背景 / 技术技能 / 项目经历 / 自我评价 | Education / Skills / Experience / Summary (optional) |
| Order | Education first for new grads | Experience-first common; Education last for experienced |
| Photo / age / marital | Often expected | Never include (bias-screened; some ATS reject) |
| Self-section | 自我评价 or 个人亮点, 3–5 bullets | Short Summary (2–3 lines) or omit entirely |
| Language of tech terms | English tech terms inline (Python、MCP) | English throughout |

## 7. ATS & delivery

- Standard headings only; no icons, images, or multi-column layouts.
- Keywords from the target JD appear 2–3 times, folded in naturally.
- Deliver PDF. zh: `姓名-岗位名-联系方式.pdf`
  (e.g. `张三-AI Agent开发工程师-138xxxx.pdf`); en:
  `FirstName-LastName-Role.pdf` (e.g. `Jordan-Lee-AI-Agent-Engineer.pdf`).
- One resume per JD: adjust skill order and project emphasis, never bulk-send
  one version.
- zh: best sending window is weekday mornings 9–11, referrals beat cold
  applies; en: referrals and targeted applications dominate; generic
  mass-apply rarely works.

## 8. Pre-send checklist

- [ ] Keywords match the target JD
- [ ] Every project has quantified results
- [ ] Contact info complete (phone, email, GitHub)
- [ ] Market conventions respected (photo/age rules, section order)
- [ ] No typos; timeline has no unexplained gaps
- [ ] PDF format, standard file name
- [ ] Proficiency levels won't collapse under probing
- [ ] Every line defensible in an interview — anything else gets cut

## 9. AI Agent role specifics (what makes this resume not a backend resume)

1. Source-code understanding of at least one framework beats API fluency.
2. Protocol understanding (MCP) beats framework familiarity.
3. End-to-end delivery (prompt → system → deployment → metric) beats
   single-point skills.
4. Open-source contributions and technical writing are strong differentiators.
